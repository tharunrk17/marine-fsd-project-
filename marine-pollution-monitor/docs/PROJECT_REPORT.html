ABSTRACT

Marine ecosystems worldwide face catastrophic environmental degradation driven by unchecked anthropogenic plastic waste deposition, toxic industrial discharges, and recurrent coastal oil spills. Existing marine pollution surveillance systems remain predominantly fragmented, relying on manual data logs, retrospective sampling, and disconnected municipal response desks. This lack of automated, centralized data synthesis creates critical latency between pollutant detection and remediation deployment, exacerbating marine habitat devastation and endangering public health.

To resolve these challenges, this project introduces MarineWatch, a unified full-stack web-based Marine Pollution Monitoring and Incident Assessment System architected on the MERN stack (MongoDB, Express.js, React 19, and Node.js). The system bridges citizen observation, environmental enforcement officers, and non-governmental organizations (NGOs) through an evidence-based digital platform. MarineWatch features a multi-tiered Role-Based Access Control (RBAC) mechanism governed by JSON Web Tokens (JWT) and Bcrypt hashing, ensuring secure authorization across Administrators, Environmental Officers, NGO Coordinators, and Citizens.

The platform incorporates an interactive geospatial incident reporting module powered by React-Leaflet, allowing verified reporting of plastic dumps, chemical effluents, and oil slicks with precise GPS coordinates, severity markers (Low, Medium, High), visual media links, and a lifecycle status tracking pipeline (Reported → Investigating → Cleanup Planned → Resolved). In parallel, continuous multi-parameter water-quality telemetry records pH, Dissolved Oxygen (mg/L), Turbidity (NTU), Temperature (°C), Oil Index, and Microplastic Density across coastal stations, automatically classifying status into Good, Watch, or Poor.

An administrative analytics engine utilizing MongoDB Aggregation Pipelines and Recharts renders dynamic longitudinal distributions, source breakdowns, and volunteer response metrics. Furthermore, volunteer mobilization for cleanup drives enables direct material recovery auditing (kg of plastic collected, litres of oil salvaged). The platform demonstrates high fault tolerance, clean RESTful API standards, responsive glassmorphic UI, and robust full-stack software engineering methodologies.

CHAPTER 1

INTRODUCTION

1.1 OVERVIEW

The world ocean covers over 70% of the Earth's surface, acts as the primary climate regulator, produces over 50% of the planetary oxygen supply, and provides essential livelihood and sustenance for billions of people. However, coastal and pelagic ecosystems are under unprecedented threat due to the compounding influx of anthropogenic contaminants. Over 14 million tons of plastics enter ocean waterways annually, breaking down into hazardous microplastics that enter the marine food web. Concurrently, unmonitored chemical discharge from industrial zones and catastrophic hydrocarbon release from maritime transit vessels cause severe hypoxia, coral bleaching, and catastrophic biodiversity die-offs.

Addressing these multi-vector ecological threats requires immediate synergy between public environmental awareness, rapid civic reporting, authoritative regulatory oversight, and coordinated ground-level cleanup operations. The MarineWatch: Marine Pollution Monitoring System is conceived as a comprehensive, full-stack software application built on modern web standards (MongoDB, Express.js, React, Node.js). It digitizes the incident lifecycle, provides multi-parameter water-quality analytics, coordinates community cleanup volunteer drives, and delivers interactive visual telemetry to support data-driven maritime conservation.

1.2 PROBLEM DEFINITION

Conventional marine pollution management in developing and coastal regions suffers from severe organizational and technological gaps:

  • Lack of Centralized Incident Telemetry: Public sightings of oil slicks, chemical plumes, and beach debris accumulations are typically reported through disconnected telephone hotlines or fragmented social media posts, resulting in untracked cases and delayed municipal response.
  • Disconnected Sensor and Laboratory Logs: Key water quality indices (pH, Dissolved Oxygen, Turbidity, Temperature, Oil Slicks) are recorded on paper ledgers or standalone spreadsheets without temporal synchronization or geospatial visualization.
  • Absence of Field Action Traceability: Coastal cleanup operations by volunteer NGOs lack systematic tracking of tonnage collected, salvage metrics, or volunteer participation audits.
  • Lack of Role-Based Governance: Without secure authentication and role segregation, sensitive environmental violation records are susceptible to tampering or uncoordinated edits.

1.3 OBJECTIVE

The core objectives of the Marine Pollution Monitoring project are:

  • To engineer a high-performance web platform that consolidates marine pollution reporting, water quality monitoring, cleanup logistics, and visual analytics into a single unified interface.
  • To implement a robust Role-Based Access Control (RBAC) architecture using JSON Web Tokens (JWT) and encrypted password hashing, ensuring distinct privilege levels for Administrators, Environmental Officers, NGO Coordinators, and Citizens.
  • To provide an interactive geospatial mapping module using Leaflet that pinpoints pollution incidents with customized color-coded indicators, geographic coordinates, and real-time status toggles.
  • To build a comprehensive water quality telemetry module tracking pH, dissolved oxygen, turbidity, temperature, and microplastics against standardized safety thresholds.
  • To provide real-time analytical dashboards using Recharts and MongoDB Aggregation to visualize pollutant distributions, incident severity counts, and longitudinal environmental indicators.

1.4 SCOPE OF THE PROJECT

The scope of the MarineWatch platform encompasses:

  • Citizen & Field Reporting: Permitting authenticated users to report pollution incidents with geotags, category classification (Plastic, Industrial Discharge, Oil Spill, Other), and severity tags.
  • Regulatory Workflow Management: Empowering certified Environmental Officers and Admins to transition incident statuses across a 4-stage lifecycle (Reported → Investigating → Cleanup Planned → Resolved).
  • Scientific Water Quality Registry: Enabling research stations to log physical, chemical, and biological sensor metrics and compute immediate quality statuses (Good, Watch, Poor).
  • NGO Cleanup Coordination: Scheduling beach/marine cleanup events, tracking volunteer enrollments, and recording quantitative waste recovery metrics (kg of waste, kg of plastic, litres of oil).
  • Cross-Platform Accessibility: Providing a responsive, modern desktop and mobile-friendly web experience with zero barrier to entry.

1.5 MOTIVATION

The United Nations Sustainable Development Goal 14 (Life Below Water) mandates urgent global interventions to prevent and substantially reduce marine pollution of all kinds by 2025–2030. Achieving this target requires accessible digital infrastructure that empowers everyday citizens as active environmental custodians while equipping environmental authorities with reliable, real-time data pipelines. The motivation of this project is to apply modern full-stack web engineering principles to an urgent ecological crisis, demonstrating how modern web stacks can power civic action and data-driven environmental governance.

CHAPTER 2

RELATED WORK

2.1 LITERATURE REVIEW

Substantial academic and commercial research has addressed water quality telemetry and environmental incident logging. Traditional environmental surveillance relies heavily on government-operated satellite remote sensing (e.g., European Space Agency Sentinel-1 Synthetic Aperture Radar for oil spill tracking) and fixed ocean buoys. While effective for macroscopic open-ocean phenomena, these systems exhibit major blind spots in coastal zones, nearshore estuaries, and localized beach regions where municipal plastic dumping and illegal industrial sewer discharging occur.

Recent studies by environmental informatics researchers highlight the transformative impact of crowdsourced citizen sensing. Platforms such as the Ocean Conservancy's Clean Swell app demonstrate that citizen reports provide dense localized spatial data. However, existing applications are frequently siloed—Clean Swell focuses strictly on beach litter item tallies without water quality chemical metrics, while municipal water portals remain locked behind closed government intranets without public access. MarineWatch closes this gap by synthesizing crowdsourced field reports, scientific sensor metrics, and volunteer mitigation onto an open REST-driven MERN platform.

2.2 EXISTING SYSTEM

The prevailing methodologies employed by coastal municipalities and environmental protection agencies present the following bottlenecks:

  • Manual Reporting Pipelines: Incidents are logged via paper complaints or unstructured email notices, causing days of delay before an inspection team is dispatched.
  • Siloed Spreadsheets: Water quality stations store parameter measurements locally in disconnected Excel spreadsheets, inhibiting longitudinal trend analysis.
  • Lack of Real-time Spatial Pinpointing: Reports lack verified geographic coordinates and interactive maps, leading to navigational confusion during field operations.
  • Zero Public Transparency: Citizens who report pollution never receive status updates on whether the violation was investigated or resolved.
  • Static Visualizations: Environmental administrators lack automated chart generation, necessitating manual report preparation for management reviews.

2.3 PROPOSED SYSTEM

The proposed MarineWatch System delivers a modern, reactive single-page application built on the MERN technology stack:

  • Unified Multi-Tier Architecture: Decoupled React single-page frontend communicating via asynchronous JSON REST APIs with a scalable Express/Node.js backend and a MongoDB document database.
  • Role-Based Access Control (RBAC): Four distinct persona levels—Admin (complete governance & deletion rights), Officer (status lifecycle & water quality validation), NGO (cleanup drive management), and Citizen (incident reporting and volunteer registration).
  • Geospatial Map Visualization: Interactive Leaflet map embedding dynamic color-coded markers (Blue for Plastic, Orange for Industrial, Red for Oil Spills) with coordinate pickers and interactive popups.
  • Lifecycle Status Tracking: Strict State-Machine lifecycle for every report: Reported → Investigating → Cleanup Planned → Resolved.
  • Continuous Water Quality Indexing: Structured schemas for monitoring pH, Dissolved Oxygen, Turbidity, Microplastics, and Oil Index with automated status labeling.
  • Responsive Analytics Dashboard: Live aggregation pipelines computing incident summaries, source distributions, severity breakdowns, and volunteer impact stats rendered through Recharts.

3.1.1 Functional Requirements

  • User Management: Secure user registration, authentication with JWT tokens, role attribution, and persistent session recovery via browser LocalStorage.

  • Usability & Responsiveness: Fluid UI adapting seamlessly to desktop monitors (1920x1080), laptops, tablets, and smartphones.
  • Reliability & Data Integrity: Strict schema validation via Mongoose, transactional error handling, and graceful API fallback messages.

4.1 SYSTEM ARCHITECTURE

The architecture of MarineWatch follows a clean Three-Tier Client-Server distributed design. The Presentation Tier comprises a React 19 Single Page Application (SPA), the Application Tier hosts an Express 5 REST API on Node.js, and the Data Tier leverages MongoDB for flexible document persistence.

4.2 MODULE DESCRIPTION

  1. Authentication & User Authorization Module: Implements secure registration and login using bcryptjs for cryptographic hashing and jsonwebtoken for stateless JWT token creation. Handles role decoding and protects routes based on user role (Citizen, NGO, Officer, Admin).
  2. Pollution Incident Management Module: Allows authenticated users to report pollution sightings with category, severity, description, and GPS coordinates. Powers filtering by source, severity, and status, and enables officers to update incident lifecycles.
  3. Geospatial Map Module: Integrates Leaflet to render high-resolution OpenStreetMap tiles. Displays color-coded markers for each pollution incident with clickable cards displaying severity, images, and coordinates.
  4. Water Quality Telemetry Module: Collects readings for physical and chemical parameters across stations (pH, Dissolved Oxygen, Turbidity, Temperature, Oil Index, Microplastics) and evaluates ecological safety levels.
  5. Cleanup Operations & Volunteer Module: Coordinates beach and ocean cleanup campaigns, manages citizen volunteer registrations, and records quantitative metrics for waste and plastic collected.
  6. Analytics & Dashboard Aggregation Module: Executes MongoDB aggregation queries to compute totals, status ratios, source counts, and historical water telemetry trends rendered in interactive Recharts charts.

CHAPTER 5

IMPLEMENTATION

5.1 IMPLEMENTATION OVERVIEW

The implementation of MarineWatch is realized through a modern JavaScript ecosystem adhering to ECMAScript modules (ESM). The backend server is initialized in server.js with Express 5, configured with CORS middleware to permit authenticated client interactions across localhost and deployment domains. Environment configuration is centralized via dotenv. Database persistence is established through Mongoose ODM, utilizing asynchronous connection pooling.

The frontend is built using React 19 bundled with Vite 7 for rapid Hot Module Replacement (HMR). Routing is handled by react-router-dom (v7), providing public routes for landing and authentication, and protected layout routes for the authenticated operational dashboard. State management is coordinated through a custom AuthContext that persists session tokens in localStorage, while Axios interceptors automatically attach the Bearer token to all outgoing HTTP request headers.

5.2 KEY FUNCTIONS (CODE EXPLANATION)

1. Asynchronous Database Connection (backend/src/config/db.js)

The connectDB() function establishes connection to the MongoDB cluster. It verifies the presence of the MONGO_URI environment variable, handles connection exceptions gracefully, and ensures the Express application only begins listening on its port once database readiness is confirmed.

2. JWT Verification and Role-Based Middleware (backend/src/middleware/auth.js)

The protect middleware intercepts incoming HTTP requests, extracts the authorization header, verifies the JWT signature against process.env.JWT_SECRET, and attaches the sanitized user document (excluding password hash) to req.user. The companion allowRoles(...roles) middleware validates that the authenticated user possesses the required privileges before delegating execution to the route controller.

3. Generic Factory CRUD Controller (backend/src/controllers/crudController.js)

To achieve modularity and code reusability, a higher-order factory function crudController(Model, ownerField, populate) generates standard RESTful handlers (list, get, create, update, remove) for any Mongoose model. It integrates dynamic text regex searching across string schema paths and guarantees proper ownership binding.

4. Dashboard Multi-Stage Aggregation Pipeline (backend/src/controllers/dashboardController.js)

The dashboard controller utilizes MongoDB Aggregation Pipelines to process large volumes of environmental data in real time. It calculates total incident counts, aggregates active vs. resolved ratios, groups pollution incidents by source, and aggregates total waste and oil recovered across all cleanup operations in a single coordinated query.

5. Interactive Leaflet Map Integration (frontend/src/pages/Reports.jsx)

The incident reporting interface integrates react-leaflet to render interactive maps. Using L.divIcon, customized SVG pinpoint markers are generated dynamically based on pollutant type. Clicking any marker reveals a popup containing severity tags, GPS coordinates, reporter information, and direct links to update incident status.

6. Password Hashing and Registration

backend/src/controllers/authController.js (register)

export async function register(req, res) {
  const { name, email, password, role } = req.body;
  if (!name || !email || !password) {
    return res.status(400).json({ message: 'Name, email and password are required' });
  }
  const exists = await User.findOne({ email: email.toLowerCase() });
  if (exists) {
    return res.status(409).json({ message: 'Email already registered' });
  }
  const validRoles = ['admin', 'officer', 'ngo', 'citizen'];
  const userRole = validRoles.includes(role) ? role : 'citizen';

  const hash = await bcrypt.hash(password, 10);
  const user = await User.create({
    name,
    email: email.toLowerCase(),
    password: hash,
    role: userRole
  });

  res.status(201).json({
    token: makeToken(user.id),
    user: { id: user.id, name: user.name, email: user.email, role: user.role }
  });
}

backend/src/controllers/authController.js (login)

export async function login(req, res) {
  const { email, password } = req.body;
  if (!email || !password) {
    return res.status(400).json({ message: 'Email and password are required' });
  }
  const user = await User.findOne({ email: email.toLowerCase() });
  if (!user || !(await bcrypt.compare(password, user.password))) {
    return res.status(401).json({ message: 'Invalid email or password' });
  }
  res.json({
    token: makeToken(user.id),
    user: { id: user.id, name: user.name, email: user.email, role: user.role }
  });
}

8. Authentication Middleware

backend/src/middleware/auth.js

import jwt from 'jsonwebtoken';
import User from '../models/User.js';

export async function protect(req, res, next) {
  try {
    const header = req.headers.authorization || '';
    if (!header.startsWith('Bearer ')) return res.status(401).json({ message: 'Authentication required' });
    const token = header.slice(7);
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = await User.findById(decoded.id).select('-password');
    if (!req.user) return res.status(401).json({ message: 'User not found' });
    next();
  } catch {
    res.status(401).json({ message: 'Invalid or expired token' });
  }
}

export function allowRoles(...allowedRoles) {
  return (req, res, next) => {
    if (!req.user || (!allowedRoles.includes(req.user.role) && req.user.role !== 'admin')) {
      return res.status(403).json({ message: `Access restricted to: ${allowedRoles.join(', ')}` });
    }
    next();
  };
}

export function adminOnly(req, res, next) {
  if (req.user?.role !== 'admin') return res.status(403).json({ message: 'Admin access required' });
  next();
}

    const { search, source, severity, status } = req.query;
    const query = {};
    if (search) {
      query.$or = [

      ];

    if (status && status !== 'All') query.status = status;

});

async function submit(e) {
  e.preventDefault();
  setLoading(true);
  setError('');
  try {
    if (isRegister) {
      const r = await api.post('/auth/register', { name, email, password, role });
      login(r.data.token, r.data.user);
    } else {
      const r = await api.post('/auth/login', { email, password });
      login(r.data.token, r.data.user);
    }
    navigate('/dashboard');
  } catch (err) {
    setError(err.response?.data?.message || 'Authentication failed.');
  } finally {
    setLoading(false);
  }
}
